# HID-Mouse v1 需求基线

状态：`APPROVED`
适用平台：Windows 11 x64
最近整理：2026-10-03

本文档汇总当前用户已经明确的决策。用户已在 2026-09-28 确认按文档开始开发，
并将“可选调试日志”和“单动作捕获转发测试”加入当前实施增量。

## 1. 产品目标

HID-Mouse 是通用输入转发兼容层，不是目标程序适配器。程序观察当前交互会话
中的鼠标、触控提升鼠标、RDP 和软件注入输入，识别可以可靠识别的来源，只将
策略判定为不兼容的鼠标兼容事件吞掉并通过 WinUHid 虚拟鼠标重新发送。

Windows 负责命中测试和选择事件目标。运行时代码不得识别目标进程、窗口、
控件或应用名称。

## 2. 已确认需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| REQ-01 | v1 支持 Windows 11 x64，使用 C++20、CMake 和 MSVC。 | Release x64 可构建；不承诺其他平台或架构。 |
| REQ-02 | 程序是前台终端程序，不提供 GUI、托盘、服务、计划任务或后台进程。 | 终端关闭后程序停止；仓库不创建自启动项。 |
| REQ-03 | `run` 必须在提升权限的 PowerShell 7 或其他管理员终端中运行。 | 非提升进程在安装任何钩子前失败。 |
| REQ-04 | 驱动必须由用户预先安装。程序不得安装、下载、更新或签名驱动，也不得修改测试签名、Secure Boot 或启动配置。 | 驱动缺失或不兼容时给出诊断并失败退出，系统不发生安装类变更。 |
| REQ-05 | 使用一只五键、相对移动、垂直/水平滚轮的 WinUHid 虚拟鼠标。 | 能发送相对移动、左/右/中/X1/X2 和双向滚轮。 |
| REQ-06 | 转发逻辑必须与目标应用无关。 | 源码和配置中不存在 zzz、Codex 或其他目标应用规则。 |
| REQ-07 | 默认采用严格来源策略：自身虚拟鼠标回声和已兼容 HID 输入放行；可可靠识别的不兼容来源转换；未知来源放行。 | 分类不确定时不吞输入。 |
| REQ-08 | 保留原生 Pointer/Touch 流，只处理其鼠标兼容提升事件。不得为了捕获而把触控全局注册到本程序。 | 触控滚动和多点触控仍由 Windows/目标应用处理。 |
| REQ-09 | 失败策略是 fail-open。只有在输出端健康且事件已进入有界转发队列时才允许吞掉原事件。 | 队列满、后端错误、分类未知或安全状态异常时原输入放行。 |
| REQ-10 | 退出和故障恢复必须发送中立报告，释放所有由虚拟鼠标保持的按钮。 | 正常退出、Ctrl+C、可处理异常和紧急旁路均不遗留按下状态。 |
| REQ-11 | 固定紧急旁路键暂定为 `Ctrl+Alt+Shift+F12`；注册失败则 `run` 不启动。 | 触发后停止吞输入、发送中立报告、卸载钩子并退出。 |
| REQ-12 | 提供 `doctor`、`probe`、`run` 三个命令。 | 三个命令的副作用和失败结果符合第 4 节。 |
| REQ-13 | 支持正常解锁的当前交互桌面；不支持 UAC 安全桌面、锁屏、登录桌面、Session 0 或其他用户会话。 | 文档和诊断明确报告该边界。 |
| REQ-14 | 只有传入 `--log <path>` 时才写入调试日志。日志必须说明时间来源、系统与会话、设备情况、观察到的操作、分类/决策、转发结果、错误和清理结果。 | JSONL 日志可逐行解析；不记录目标进程、窗口标题、控件或键盘文本。 |
| REQ-15 | 当前增量提供 `run --once click\|move\|wheel`，捕获一个测试样本后停止观察，在可配置延时结束后通过 WinUHid 重放并退出。 | 原事件始终放行；click 捕获左键按下+释放，move 捕获一个非零移动报告，wheel 捕获一个滚轮报告；捕获后立即停止 Hook/Raw Input，延时期间其他输入不被本程序观察或转发。 |
| REQ-16 | C-Once 的回放延时只用于实机测试准备，不得进入正式持续转发语义。 | 正式模式逐报告低延迟转发；长移动由连续小报告组成，不等待手势结束，也不引入固定 200 ms 等聚合延时。 |

## 3. 来源分类与策略

规范化来源类别：

| 来源类别 | 默认动作 | 说明 |
| --- | --- | --- |
| `self_virtual_hid` | 放行且不再次发送 | 防止输出回环。 |
| `compatible_hid` | 放行 | 已经具有目标所需的 HID 语义。 |
| `software_injected` | 转换 | 仅在低级钩子注入标志足以识别时。 |
| `touch_promoted_mouse` | 转换 | 只替换鼠标兼容提升事件；原生触控不变。 |
| `rdp_mouse` | 转换 | 仅在当前环境能可靠识别时。 |
| `unknown` | 放行 | 不以猜测为依据吞输入。 |

上述映射是来源策略，不是目标程序策略。若 RDP 或第三方远控输入在公开 Win32
接口上不可区分，v1 不得偷偷把它归类为其他来源；必须由 `probe` 证据决定是否
存在安全的通用识别规则。

## 4. 命令契约

### `hid-mouse doctor`

依次检查：

1. 操作系统与架构；
2. 管理员令牌；
3. 应用目录中的 WinUHid 用户态 DLL 与必要导出；
4. `WinUHidGetDriverInterfaceVersion()`；
5. 创建并立即销毁虚拟鼠标的烟雾测试。

`doctor` 不安装钩子、不持续运行、不发送业务输入。临时创建虚拟设备属于已知
且可撤销的诊断副作用。

### `hid-mouse probe`

只观察并记录来源判定所需元数据，不吞输入、不创建用于转发的虚拟鼠标、不发送
输入。日志不得记录按键文本、目标进程、窗口标题或控件信息。

可用 `--duration <seconds>` 限制前台观察时间；省略时运行到 Ctrl+C。只有指定
`--log <path>` 才创建日志文件。

### `hid-mouse run`

必须按顺序完成管理员检查、依赖检查、驱动接口检查、虚拟鼠标创建、安全热键
注册，然后才允许安装输入钩子。任一步失败都不得留下钩子或虚拟设备。

当前增量只实现受控测试形式：

```powershell
hid-mouse run --once click --replay-delay 3 --log click.jsonl
hid-mouse run --once move --replay-delay 3 --log move.jsonl
hid-mouse run --once wheel --replay-delay 3 --log wheel.jsonl
```

该模式不会吞掉原事件。它等待下一次匹配样本，记录来源证据，立即停止 Hook 与
Raw Input 观察，然后等待回放延时。延时期间用户可切换、聚焦和定位目标；其他
输入仍由 Windows 处理，但本程序直接忽略。延时结束后通过虚拟鼠标重放一次并
退出。捕获超时默认 30 秒，可用 `--timeout <seconds>` 调整；回放延时默认 3 秒，
可用 `--replay-delay <seconds>` 在 0 到 30 秒内调整。

move 的单样本测试只重放一个输入报告，不代表完整长移动。正式持续模式应立即
转发组成长移动的每个报告，不使用 C-Once 的准备延时。这不是完整 v1 已完成的
证据。

### 调试日志

日志采用 UTF-8 JSON Lines，每条至少包含：

- schema 版本、递增序号和事件类型；
- UTC 墙钟时间及其 Windows 来源；
- 基于 `QueryPerformanceCounter` 的单调时间和频率；
- 命令、进程、权限、Windows 版本、会话和远程会话标记；
- Raw Input 设备句柄、设备路径与公开设备信息；
- 钩子消息、坐标、按键/滚轮值、flags、`dwExtraInfo` 和来源分类；
- 采取的动作、是否阻止原事件、WinUHid 调用结果与 Win32 错误码；
- 钩子卸载、虚拟按钮复位、设备销毁和文件关闭结果。

钩子回调不得直接写日志；日志必须在回调返回后的消息处理路径写入。

## 5. v1 验收场景

这些名称只允许出现在测试计划和测试记录中：

1. zzz：RDP/待验证来源的左键和移动经虚拟鼠标后可用；输出采用相对移动。
2. Codex：触控产生的一次左键点击能点击关闭按钮；不要求其他 Codex 行为。
3. 本地触控：滚动、多点触控和系统手势不因程序运行而失效。
4. 物理鼠标：严格策略下保持正常工作。
5. Sunshine：普通鼠标模式与原生触控模式分别采样；能识别时按来源策略处理，
   不能识别时安全放行并在诊断中说明。
6. 安全恢复：Ctrl+C、紧急旁路、后端失败和队列压力均不得造成鼠标永久按下或
   全局输入被持续阻断。

## 6. 非目标

- 不安装或分发 WinUHid 驱动。
- 不为任何应用维护窗口、坐标或控件特例。
- 不绕过 UAC、安全桌面、反作弊或安全产品。
- 不实现键盘转发。
- 不提供 GUI、Web UI、服务、托盘或后台常驻。
- 不保证在未经过 `probe` 验证的远控实现上转换输入。
